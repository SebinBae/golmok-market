# 0001. 하나의 레포에 core / api / web 멀티모듈

- 상태: 채택
- 날짜: 2026-09-09

## 맥락

같은 도메인 위에 REST(api)와 SSR(Thymeleaf) 두 가지 표현 계층을 올려
비교하는 것이 이 프로젝트의 학습 목표 중 하나다.

구현 방법으로 두 가지를 검토했다.

- (A) 백엔드 레포를 두 개로 분리
- (B) 하나의 레포에 Gradle 멀티모듈, 실행 가능한 bootJar 2개

## 결정

(B)를 택한다.

```
golmok/
  core/   ← 도메인 + 애플리케이션 서비스. HTTP를 모름. jar만 생성
  api/    ← REST 어댑터. JSON, JWT. bootJar
  web/    ← SSR 어댑터. Thymeleaf, 세션, 폼. bootJar
```

`api`와 `web`은 서로를 모르고, 둘 다 `core`만 의존한다.

## 근거

레포를 분리하면 `core`가 두 벌이 된다. 엔티티·검증 규칙·예외 계층·마이그레이션을
두 번 관리해야 하고, 반드시 어긋난다.

더 중요한 것은 **두 버전을 만드는 목적 자체가 사라진다**는 점이다.
하나의 core에 어댑터 둘을 붙이는 이유는 서비스 계층에 HTTP 관심사가
새어나가는 것을 발견하기 위해서다. core를 복사하면 각자 편한 대로 짜게 되어
그 누수가 영영 드러나지 않는다.

## 결과

- 컴포넌트 스캔 문제를 피하기 위해 패키지를 `com.golmok`으로 통일한다
- ArchUnit으로 의존 방향을 강제한다
- React SPA는 별도 레포(`golmok-web`)로 둔다. npm 생태계와 빌드 도구가 다르다
