# 0005. 동시 예약 경합 제어를 의도적으로 연기

- 상태: 연기 (결정하지 않음)
- 날짜: 2026-09-09

## 맥락

"같은 시점에 상품당 활성 Trade는 하나"라는 제약이 필요하다.
그런데 0004에 따라 Trade가 Product를 직접 참조하지 않으므로
DB 유니크 인덱스를 바로 걸 수 없다.

선택지:

- (A) `productId`를 Trade에 비정규화 + 부분 유니크 인덱스
  → DB가 막아준다. 안전하고 단순하지만 데이터 중복
- (B) 정규화 유지 + 비관적 락 또는 분산락
  → 깨끗하지만 락 설계를 직접 해야 함

## 결정

**지금 정하지 않는다.** 이것은 결정 실패가 아니라 의도적 연기다.

진행 방법:

1. 채팅/거래 구현 단계에서 **아무 제약 없이** 만든다
2. 동시 요청 테스트로 활성 Trade가 2개 생기는 것을 재현한다
3. 그 결과를 근거로 (A) 또는 (B)를 고른다
4. 이 ADR을 수정하지 않고 **새 ADR로 뒤집는다**

## 근거

지금 (A)를 고르면 DB가 막아주니 안전하지만,
보호 장치 없이 만들었을 때 실제로 어떻게 깨지는지 볼 기회가 사라진다.
"가벼운 대안 먼저 → 한계 측정 → 교체" 원칙이 적용될 자리다.
