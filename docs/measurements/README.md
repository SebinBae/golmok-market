# 성능 측정 기록

"가벼운 대안 먼저 → 한계 측정 → 교체" 원칙에 따라,
개선 전후 수치를 여기에 남긴다.

## 기록 형식

파일명: `YYYYMMDD-대상.md` (예: `20261001-product-list-n-plus-one.md`)

각 문서에 담을 것:

1. **측정 조건** — 데이터 규모, 프로필, 도구, 반복 횟수
2. **Before** — 무엇이 어떻게 느렸는지, 쿼리 개수, 응답 시간
3. **원인** — 왜 느렸는지
4. **개선** — 무엇을 어떻게 바꿨는지
5. **After** — 같은 조건에서 재측정한 수치
6. **판단** — 이 교체가 값어치가 있었는지, 다음에 뭘 볼지

수치 없이 "빨라졌다"고 쓰지 않는다.

## 측정 대상 (예정)

| 순서 | 대상 | Before | After |
|---|---|---|---|
| 1 | 베이스라인 (mock 20만 건 목록 조회) | — | — |
| 2 | N+1 (판매자·이미지) | 소박한 구현 | fetch join / `@BatchSize` |
| 3 | 목록 인덱스 | 없음 | `(region_id, status, deleted_at, created_at DESC)` |
| 4 | 페이징 | `OFFSET` | 커서 방식 |
| 5 | 검색 | `LIKE` | Elasticsearch |
| 6 | 후속 처리 | 동기 | `@Async` → Kafka |
