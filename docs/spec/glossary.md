# 용어 사전 (Glossary)

> 이 문서는 golmok 프로젝트에서 쓰는 도메인 용어를 고정한다.
> 코드, 문서, 커밋 메시지, Claude Code 프롬프트에서 모두 이 용어를 쓴다.
> 새 용어가 등장하면 코드보다 먼저 여기에 추가한다.

---

## 핵심 원칙

용어가 흔들리면 코드도 흔들린다. 특히 다음 세 쌍은 자주 혼동되므로 구분을 명확히 한다.

- **채팅방 ≠ 거래** — 채팅방은 여러 개, 거래는 그중 하나에서만 파생된다
- **동네 ≠ 지역** — "동네"만 쓴다. "지역"은 쓰지 않는다
- **삭제 ≠ 거래완료** — 삭제는 판매자가 상품을 내리는 것, 거래완료는 거래가 성사된 것

---

## 사용자 영역

### 사용자 (User)
서비스에 가입한 사람. 프로필 정보(닉네임, 휴대폰 번호, 동네)를 가진다.
**인증 정보는 사용자가 직접 갖지 않는다.** 인증수단(UserCredential)으로 분리한다.

### 인증수단 (UserCredential)
사용자가 로그인하는 방법 하나를 나타낸다. 한 사용자가 여러 인증수단을 가질 수 있다.

- `LOCAL` — 이메일 + 비밀번호
- `KAKAO`, `GOOGLE` — 소셜 로그인 (M1에서는 구조만 두고 구현하지 않음)

이메일은 사용자가 아니라 **인증수단에 속한다.** 소셜에서 받아온 이메일은 우리가 검증한 것이 아니므로 비밀번호 재설정에 쓰지 않는다.

### 판매자 (Seller)
상품을 등록한 사용자. 별도 엔티티가 아니라 **맥락상의 역할 이름**이다.

### 구매자 (Buyer)
거래에서 물건을 받는 쪽 사용자. 마찬가지로 역할 이름이며 별도 엔티티가 아니다.

---

## 동네 영역

### 동네 (Region)
사용자와 상품이 속하는 지역 단위. **행정동 기준**이다.

- 사용자는 동네를 **최대 2개**까지 가진다
- 상품은 **등록 시점의 동네에 고정**된다. 판매자가 동네를 바꿔도 이미 등록된 상품은 움직이지 않는다
- 초기 범위는 **서울 강북구**로 한정한다. 구조는 전국 확장이 가능하되 데이터만 좁게 넣는다

"지역", "지역구", "위치"라는 말은 쓰지 않는다. 항상 **동네**다.

### 활성 동네 (Active Region)
사용자가 가진 2개 동네 중 지금 보고 있는 쪽. 서버에 저장하지 않고 **요청 파라미터로 받는다.**

### 범위 설정 (Region Scope)
내 동네에서 얼마나 먼 동네까지 상품을 볼지 정하는 설정.
**M1에서는 만들지 않는다.** 내 동네만 보인다. Region에 중심 좌표만 미리 넣어둔다.

## 상품 영역

### 상품 (Product)
판매자가 등록한 물건 하나.

### 상품 상태 (ProductStatus)
- `ON_SALE` (판매중) — 등록 직후 기본값
- `RESERVED` (예약중) — 거래가 잡힌 상태
- `SOLD` (거래완료) — 거래가 끝난 상태

M1에서는 `RESERVED`로 가는 경로가 없다(채팅이 없으므로). 그래도 **enum에는 처음부터 3개를 정의한다.**

### 나눔
가격이 0원인 상품. 별도 플래그를 두지 않고 **`price = 0`이 곧 나눔**이다.

### 상품 이미지 (ProductImage)
상품에 딸린 사진. 상품 하나에 여러 장이 붙고 **순서를 가진다.**

### 삭제 (Soft Delete)
판매자가 상품을 내리는 것. **실제로 지우지 않고 `deleted_at`에 시각을 기록한다.**
채팅방이 상품을 참조하므로 물리 삭제하면 채팅 이력이 깨진다.

## 거래 영역

> M1에서는 **설계만 하고 구현하지 않는다.**

### 채팅방 (ChatRoom)
특정 상품에 대해 판매자와 구매자 한 명이 나누는 대화 공간.

- 상품 하나에 채팅방이 **여러 개** 생긴다
- 같은 상품 + 같은 구매자면 채팅방은 하나만 생긴다
- 예약이 취소되어도 **채팅방은 남는다**
- 거래가 완료되면 **채팅방은 닫힌다**

### 채팅방 상태 (ChatRoomStatus)
- `OPEN` — 대화 가능
- `CLOSED` — 거래 완료로 닫힘

### 거래 (Trade)
채팅방에서 파생된, 판매자와 구매자 한 쌍의 실제 거래 약속.

- **채팅방 없이는 거래가 생기지 않는다.** 예약은 항상 채팅방 안에서 시작된다
- 그래서 거래는 채팅방을 참조하고, **상품을 직접 참조하지 않는다**
- 상품 하나에 거래가 여러 번 생길 수 있다(예약 → 취소 → 다른 사람과 예약)
- 같은 시점에 **활성 거래는 상품당 하나뿐**이다

> **네이밍 주의**: `Transaction`이라는 이름은 쓰지 않는다.
> Spring/JPA에서 `@Transactional`, `TransactionManager` 등 DB 트랜잭션을 뜻하는 단어와 정면으로 충돌해서
> 코드를 읽을 때 매번 어느 쪽인지 판단해야 한다. `Trade`를 쓴다.

### 예약
거래가 생성되는 것. 상품 상태가 `RESERVED`로 바뀐다. **동사로만 쓰고 엔티티 이름으로는 쓰지 않는다.**

## 인증/보안 영역

### 비밀번호 재설정 토큰 (PasswordResetToken)
비밀번호를 잊었을 때 발급하는 일회용 토큰. `LOCAL` 인증수단에만 발급된다.
**평문으로 저장하지 않고 해시해서 저장한다.**

### 인증 코드 (VerificationCode)
휴대폰 번호 확인에 쓰는 단기 코드. 아이디(이메일) 찾기에서 사용한다.
M1에서는 실제 SMS를 보내지 않고 **콘솔에 출력한다.**

### 마스킹
아이디 찾기 결과로 이메일을 보여줄 때 일부를 가리는 것. `hy****@gmail.com` 형태.
가리지 않으면 휴대폰 번호를 넣어 가입 여부를 알아내는 열거 공격이 가능해진다.

## 아키텍처 용어

### core
도메인과 애플리케이션 서비스를 담는 모듈. **HTTP를 전혀 모른다.** 실행되지 않는 라이브러리다.

### api
REST 어댑터 모듈. JSON, JWT를 담당한다. 실행 가능(bootJar).

### web
SSR 어댑터 모듈. Thymeleaf, 세션, 폼 바인딩을 담당한다. 실행 가능(bootJar).

`api`와 `web`은 서로를 모른다. 둘 다 `core`만 의존한다.

### 어댑터 (Adapter)
`api`와 `web`을 함께 부르는 말. 같은 core에 붙는 서로 다른 표현 계층이다.

## 쓰지 않는 말

| 쓰지 않음 | 대신 |
|---|---|
| 지역, 위치 | 동네 |
| Transaction (도메인) | Trade |
| 판매글, 게시글 | 상품 |
| 회원 | 사용자 |
| 채팅 (엔티티로) | 채팅방 |
