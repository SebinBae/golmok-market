# 서비스 요구사항

> 용어는 [glossary.md](./glossary.md)를 따른다.
>
> 이 문서는 **서비스 전체**의 요구사항을 담는다. 마일스톤보다 오래 산다.
> 각 마일스톤은 이 목록에서 일부를 골라 구현한다. → [milestones/](../milestones/)

**상태 표기**: `M1` = 마일스톤 1에서 구현 · `later` = 이후 마일스톤

## 6. 비기능 요구사항

### 성능 — 측정 후 개선

이 프로젝트의 원칙은 **"가벼운 대안 먼저 → 한계 측정 → 교체"**다.
아래 항목은 처음부터 최적화하지 않고, 측정으로 문제를 확인한 뒤 개선한다.
결과는 `docs/measurements/`에 before/after로 기록한다.

| ID | 항목 | M1 | 이후 |
|---|---|---|---|
| PERF-01 | 목록의 판매자·이미지 조회 | N+1 발생하는 채로 | fetch join / `@BatchSize` |
| PERF-02 | 목록 페이징 | `OFFSET` | 커서 방식 |
| PERF-03 | 목록 인덱스 | 없음 | `(region_id, status, deleted_at, created_at DESC)` |
| PERF-04 | 검색 | `LIKE` | Elasticsearch |
| PERF-05 | 후속 처리 비동기화 | 없음 | `@Async` → Kafka |

**측정 조건**: dev 프로필 mock 상품 20만 건, 판매자 수천 명 규모.
판매자를 소수로 만들면 조인 캐시에 가려 N+1이 드러나지 않는다.
